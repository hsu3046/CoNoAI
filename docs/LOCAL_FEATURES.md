## 실행

```bash
cd web
npm run dev -- --port 3100
```

추가 패키지/DB 키 없이 실행한다. 브라우저에서 `http://localhost:3100/#records`를 연다.
`docs/fixtures/score-v1.json`은 실제 노래 결과가 아닌 92점 테스트 기록이다. 앱/웹의 가져오기로 왕복 검증한다. 예제 날짜는 고정이므로 다른 주에는 주간 순위에 나오지 않는다.

- Mac: `~/Library/Application Support/space.knowai.cono/scores.json`
- 웹: 기본 `web/.local-data/store.json`, `CONO_DATA_DIR`로 별도 폴더 선택 가능
- 웹 파일에는 테스트 프로필·점수·공개 상태·의견만 저장한다. 목소리·음원·음정 프레임은 포함하지 않는다.
- `.local-data`는 Git과 Next 빌드 추적에서 제외한다. 별도 `CONO_DATA_DIR`는 저장소 밖의 경로를 사용한다.
- UI 검증 서버는 `/tmp/cono-feature-verification-20261002`를 사용해 기본 사용자 데이터와 분리했다.

## JSON 계약

`{ "schemaVersion": 1, "records": [...] }`, 최대 1,000곡·1 MB.

각 기록: UUID `id`, `songId`, `title`, `artist`, `source` (`macos`/`browser`/`demo`), `difficulty` (`normal`/`hard`), `keyShift` (-6…6), `score` (0…100), `notesHit`, `notesTotal`, `bestStreak`, UTC ISO-8601 `createdAt`.

- UUID·날짜·점수 범위와 `bestStreak ≤ notesHit ≤ notesTotal` 검증.
- 같은 ID·같은 내용의 재가져오기는 한 건으로 유지. 다른 브라우저/쿠키로 같은 백업을 가져오면 원 소유권을 유지하고 비공개 사본 ID를 생성한다. 같은 사용자에서 같은 백업을 반복 복원해도 중복되지 않는다. 같은 ID의 다른 내용은 전체 가져오기를 거부.
- 파일 손상·지원하지 않는 버전은 오류로 표시하며 기존 파일을 덮어쓰지 않는다.
- 웹은 디렉터리 잠금 + 임시 파일 rename으로 병렬 쓰기의 유실을 방지한다. 프로세스 강제 종료로 `.write-lock`이 남으면 서버를 모두 종료하고, 원본을 백업한 뒤 해당 잠금 폴더만 제거한다.
- Mac은 원자적 저장 성공 후 메모리를 갱신한다. 실패한 새 결과는 실행 중 메모리에 보관하고 재시도/개별 JSON 내보내기가 가능하다. 실패 중 앱을 종료하면 메모리 대기 기록은 사라질 수 있으므로 내보내기를 먼저 한다.
- Mac의 챌린지 곡 키는 플레이어 개인 보관함 ID 대신 정규화한 곡·가수 이름이다. 버전/라이브 구분은 입력 메타데이터에 따른다.

## 로컬 테스트의 범위와 DB 교체

웹의 `ScoreRepository`/`JsonRepository`가 저장소 경계다. 화면/API는 이 경계를 통해 저장한다. 기존 Supabase 초기화 코드는 호출하지 않는다. Vercel 환경에서는 파일 저장을 503으로 막아 성공한 것처럼 사라지는 저장을 방지한다.

`cono-session` HttpOnly/SameSite 쿠키는 로컬 테스트용 소유자 구분이다. 로그인·서버 검증 점수가 아니다. 쿠키 삭제 시 다른 사용자로 보이며, 먼저 JSON으로 내보내거나 원본 저장 파일을 백업해야 한다. 챌린지와 공유 링크는 같은 로컬 서버의 공개 기록만 보여 준다. localhost 링크는 다른 사람의 기기에서 열리지 않는다. 이미지/JSON 파일은 독립적으로 전달할 수 있다.

DB 연결 단계에서는 사용자 인증, 영구 소유권·내 기록 복구, 서버의 점수 검증, DB 트랜잭션/유일성 제약, 요청 제한, 데이터 보관·삭제 정책을 함께 구현한다. 현재 파일 저장소를 운영 서버로 배포하지 않는다.

## 검증

- macOS Debug 빌드 + Swift Testing 전체 80개: 새 기록 왕복·중복·범위·손상 파일 보존·재시도·삭제 검증 포함.
- 웹 `npm test`: 스키마 검증, 한국 주 경계, 동시 저장·재로딩, 실패 트랜잭션·손상 파일 보존.
- 웹 `npm run test:api`: 로컬 서버가 필요. 입력/출처 검증, 세션별 소유권, 비공개 기본값, 공개·해제, 개인 최고·난이도 분리, 의견 저장. 생성한 테스트 점수만 정리한다.
- 웹 `npm run lint`, `npm run build`.
- 실제 브라우저: 닉네임 저장 → JSON 가져오기 → 챌린지 공개 → 공유 페이지 → PNG 다운로드(1200×630) → 의견 저장. 390×844 뷰포트 공유 페이지 가로 넘침 없음. 실제 iPhone 터치 검증은 아님.

### 사용자가 확인할 시나리오

1. Mac에서 채점 후 결과의 이미지 저장·점수 공유를 눌러 확인한다.
2. ⇧⌘H에서 JSON 전체 내보내기 → 앱 재실행 후 기록 유지 → 웹 가져오기 → 다시 Mac 가져오기에서 중복이 없는지 확인한다.
3. 웹에서 챌린지에 공개한 뒤 다른 브라우저에서 공유 페이지를 확인하고, 공개 해제 후 접근이 막히는지 확인한다.
4. 재생 중 출력 장치를 48 kHz ↔ 96 kHz 또는 유선 ↔ 블루투스로 바꾸어 음높이·가사 싱크·채점 유지와 일시정지 상태 보존을 확인한다. 이 물리 장치 전환은 자동 검증하지 못했다.
